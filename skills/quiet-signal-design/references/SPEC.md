# Quiet Signal 核心视觉规范

Quiet Signal 是一种安静、清晰、克制，但具有明确识别信号的视觉语言。

它以近白表面、黑色信息层级、编辑性字体关系、细线分组和有限紫色为核心，让内容显得经过判断，而不是经过装饰。

本文件是 Quiet Signal 的唯一核心规范来源。文中的“必须”“禁止”是强制约束；“应”是默认选择；“可以”表示满足所列条件时允许使用。

## 1. 定义与边界

### 1.1 核心规范负责

- 定义视觉身份与基本气质。
- 定义跨媒介保持稳定的 Style Token 与语义角色。
- 定义层级、分组、视觉重量、颜色和表面的关系。
- 提供应用与审查 Quiet Signal 风格的判断依据。

### 1.2 核心规范不负责

- 内容生产、选题、文案改写或信息拆分。
- 页面结构、叙事顺序和平台模板。
- 网页断点、小红书画布、海报出血等媒介规格。
- Pattern、Composition、Compiler、Renderer、Runtime 或生产流水线。
- 仅凭一句宽泛指令生成完整且满意的成品。

核心规范可以约束一个已经明确的设计任务如何“看起来”，但不替用户定义任务本身。

### 1.3 与 Kit 的关系

核心规范只保存视觉身份。未来的 Web Kit、XHS Kit、Poster Kit 等可以补充：

- 实际画布、字号、边距和安全区；
- 栅格、断点、分页和导出规格；
- 组件尺寸、交互状态和平台可访问性；
- 媒介特有的实现与验证方法。

Kit 可以把核心语义映射到本媒介，但不得把自己的实现规则反向写成 Quiet Signal 的通用风格。

## 2. 设计原则

### 2.1 信号优先于装饰

每一个醒目元素都必须能说明它在提示什么。装饰不能成为画面的主语。

### 2.2 层级优先于容器

先用字号、字重、对齐、邻近和空间组织信息。只有存在真实边界、交互边界或状态边界时，才增加表面容器。

### 2.3 紫色必须有语义

紫色承担品牌信号、焦点、选择和关键变化。禁止把紫色用作无边界的大面积气氛色。

### 2.4 留白必须有作用

留白用于暂停、聚焦、呼吸或转场。未分配的剩余空间不自动等于设计。

### 2.5 视觉重量由内容获得

重要观点、关键证据和主要动作可以获得更大尺度。短标签、弱信息和空内容不能为了填满画布而被放大。

### 2.6 内容颜色保留在内容里

真实图片、截图和数据可视化可以保留自身颜色，但不能替代系统的导航、焦点、选择和状态语言。

### 2.7 克制不是没有表达

Quiet Signal 允许显著的尺度、节奏和密度变化，但变化必须由意义驱动，不能由效果欲驱动。

## 3. Token 模型

### 3.1 两层核心模型

Quiet Signal 核心只定义两层 Token：

1. **Reference Value**：原始视觉值，例如 `#7C3AED`。
2. **Core Style Token**：跨媒介保持的语义角色，例如 `color.signal.primary`。

媒介 Kit 可以增加 Implementation Token，例如 `xhs.focus.accent`，但 Implementation Token 不属于核心规范。

### 3.2 命名规则

核心 Token 使用以下格式：

```text
{category}.{role}.{variant}
```

例如：

```text
color.ink.primary
color.signal.wash
type.display.cjk
geometry.radius.small
motion.duration.fast
```

Token 名称描述用途，不描述某个组件或页面位置。核心中禁止出现 `card.*`、`hero.*`、`xhs.*` 等媒介或组件名称。

### 3.3 Token 记录要求

每个新增或修改的核心 Token 必须记录：

- 名称与类型；
- 值或关系；
- 语义角色；
- 适用条件；
- 禁止用法；
- 版本与批准状态。

## 4. 视觉基础

### 4.1 颜色

| Token | 值 | 角色 |
| --- | --- | --- |
| `color.canvas` | `#FAFAFA` | 页面与大面积工作表面 |
| `color.surface` | `#FFFFFF` | 确实需要独立边界的表面 |
| `color.surface.sunken` | `#F4F4F5` | 次级、内收或不可编辑区域 |
| `color.ink.primary` | `#0A0A0A` | 标题、主信息、主要结构线 |
| `color.ink.secondary` | `#52525B` | 正文与辅助解释 |
| `color.ink.faint` | `#A1A1AA` | 元数据与低优先级说明 |
| `color.line.default` | `#ECECEE` | 普通分组与边界 |
| `color.line.strong` | `#DCDCE0` | 需要更明确的分隔 |
| `color.signal.primary` | `#7C3AED` | 品牌、焦点、选择与关键变化 |
| `color.signal.strong` | `#6D28D9` | 需要更高对比的信号文字或状态 |
| `color.signal.soft` | `#A78BFA` | 低强度信号边界，不用于大面积铺色 |
| `color.signal.wash` | `#F3EFFE` | 有语义的轻量信号背景 |

#### 颜色使用规则

- 画面的主体必须由近白、白、黑和灰建立。
- 紫色是句点，不是背景音乐。通常只出现一个主要紫色焦点和少量状态提示。
- 不设置统一的紫色占比百分比；占用量由语义决定，但必须保持稀疏。
- 长篇正文不得使用紫色。
- 禁止紫色渐变、紫色光晕背景和大面积紫色气氛场。
- 内容图片的真实颜色不计入系统信号色占用，但不得接管全局状态语义。

### 4.2 字体角色

| Token | 默认字体 | 默认字重 | 用途 |
| --- | --- | --- | --- |
| `type.display.cjk` | `Noto Serif SC`, `Songti SC`, serif | `600–700` | 中文观点、主标题、章节标题 |
| `type.display.latin` | `Space Grotesk`, sans-serif | `600–700` | 英文标题、数字锚点、文字标识 |
| `type.body` | `Noto Sans SC`, `PingFang SC`, sans-serif | `400–600` | 正文、说明、控件文字 |
| `type.metadata` | `JetBrains Mono`, `SFMono-Regular`, monospace | `500–600` | 状态、编号、来源、技术元数据 |

#### 字体关系

- Display 负责观点和视觉锚点，Body 负责连续阅读，Metadata 负责定位和状态。
- 中文主标题应使用紧凑但不碰撞的行高，通常为字号的 `1.05–1.25`。
- 正文行高应支持连续阅读，通常为字号的 `1.6–1.85`。
- Metadata 通常为正文字号的 `0.65–0.75`，可以使用 `0.06–0.10em` 字距。
- 主标题可以使用轻微负字距；禁止通过极端负字距、横向压缩或过小字号制造密度。
- 字体回退后必须仍能区分 Display、Body 与 Metadata 三种声音。
- 具体字号由媒介 Kit 或任务 brief 决定，不属于核心固定值。

### 4.3 空间关系

核心规范定义空间层级，不固定所有媒介的像素值。Kit 先选择基础单位 `u`，再映射以下关系：

| Token | 建议关系 | 说明 |
| --- | --- | --- |
| `space.inline` | `1u` | 同级标签、图标和短控件之间 |
| `space.block` | `2u` | 标题、正文、来源等紧密内容之间 |
| `space.group` | `4u` | 一个完整信息组内部 |
| `space.section` | `8u` | 两个独立信息区之间 |
| `space.canvas` | `10u` 或由媒介决定 | 内容与画布边缘 |

必须保持：`inline < block < group < section`。

- 同一语义组内部的距离必须小于不同信息组之间的距离。
- 大留白必须能说明其暂停、聚焦、呼吸或转场作用。
- 不得用等宽、等高、等间距卡片填补没有内容的画布。
- 画布和安全区的实际数值属于 Kit。

### 4.4 几何与表面

本节包含 2026-08-23 已批准的圆角 Hybrid 决策。

| Token | 核心值 | 用途 |
| --- | --- | --- |
| `geometry.radius.structure` | `0` | 页面、章节、大内容区和结构容器 |
| `geometry.radius.ruleJunction` | `0` | 与横线相接或由横线收口的表面 |
| `geometry.radius.small` | `4px @ 1× digital` | 独立小表面、按钮和输入框 |
| `geometry.radius.pill` | `999px`，条件使用 | 极短状态、筛选或标签，不用于正文容器 |
| `geometry.line.hairline` | `1 device pixel` 或媒介等效值 | 对齐、分组和边界 |

#### 圆角边界

- 大结构与横线相接处必须保持直角。
- 独立的下层小表面、按钮和输入框可以使用轻微圆角。
- `4px` 是 1× 数字界面的参考值；高分辨率或非数字媒介可以做光学等效缩放，但不得改变其“轻微”性格。
- 禁止外层容器、内层表面和控件同时圆角化。
- 禁止以大圆角建立整体亲和感；层层圆角会产生通用 AI 产品界面的气质。

#### 线条与阴影

- 先用空间与细线分组，再判断是否需要表面。
- 默认无阴影。
- 阴影只在真实抬升、浮层或遮挡关系存在时使用，并保持低对比、宽扩散。
- 禁止把圆角、阴影和浅色填充同时用于每一个信息块。

### 4.5 图像

- 优先使用真实、来源明确且与内容直接相关的图片、截图或数据图。
- 图片可以保留内容自身颜色，系统框架仍保持中性。
- 图片必须拥有明确角色：证据、主体、情境或解释。没有角色时不应加入。
- 禁止使用装饰性 3D、抽象光球、假场景或通用 SaaS 插画填补空白。

### 4.6 动效

| Token | 值 | 用途 |
| --- | --- | --- |
| `motion.duration.fast` | `160ms` | 简单悬停、颜色或边界反馈 |
| `motion.duration.standard` | `220ms` | 常规状态切换与短距离移动 |
| `motion.duration.deliberate` | `300ms` | 需要被看清的结构变化 |
| `motion.ease.standard` | `cubic-bezier(0.22, 1, 0.36, 1)` | 快速响应、柔和收束 |

- 动效只解释反馈、状态、关系或空间连续性。
- 静态作品保持静态；禁止为了“高级感”加入循环运动。
- 持续脉冲只允许表示真实进行中的状态。
- 必须为 reduced-motion 或静态环境提供等价表达。

## 5. 视觉语法

视觉语法描述关系，不提供固定版式。

### 5.1 一条主要阅读方向

每个视图应具有一条可以被快速识别的主要阅读轴。主标题、正文起点和关键对象应形成稳定关系，辅助信息不得关闭主层级。

### 5.2 信息岛，而不是卡片墙

相关信息应优先依靠邻近、对齐、字号和细线成为一组。一个段落不自动获得一张卡片；多个信息块也不自动获得等权网格。

### 5.3 面积服从语义重量

关键观点、证据、图像或数据可以获得更大面积。短标签、弱信息和没有内容的面板必须保持紧凑。

### 5.4 有限信号

一个视图优先建立一个主要信号焦点。多个紫色对象同时竞争时，应削弱或移除其中非关键项。

### 5.5 编辑性，而非模板感

版面可以不对称，可以有尺度变化，也可以保持高密度；但关系必须清楚。Quiet Signal 不要求固定分屏、固定卡片数或固定 Hero。

## 6. 可访问性基线

- 不依赖颜色独立表达状态、选择、错误或成功。
- 主文字、正文和交互文字必须优先保证清晰度；紫色不得承担长篇正文。
- 字体回退后仍须保持信息层级和自然换行。
- 动效必须提供静态或 reduced-motion 等价表达。
- 交互环境必须具有可见焦点，具体焦点样式和输入方式由对应 Kit 验证。
- 对比度、字号下限、触控目标和平台辅助技术要求由对应 Kit 或实现环境验证。

可访问性不是为了保持风格可以被降低的变量。

## 7. 禁止项

Quiet Signal 禁止把以下表现作为默认风格：

- 紫色渐变、紫色光晕或大面积紫色气氛场；
- 玻璃拟态、彩虹霓虹和装饰性 3D；
- 外层、内层、控件层层圆角；
- 每段一个卡片的卡片墙；
- 胶囊标签泛滥；
- 没有真实状态或数据的假仪表盘；
- 不由内容关系产生的模板化分屏；
- 为填满画布制造的空洞巨型标题；
- 无意义的循环动效或悬浮效果；
- 复制某个来源产品的具体功能、页面结构或产品母题。

## 8. 综合表现与验收

一个合格的 Quiet Signal 作品应同时满足：

1. 近白、黑和灰建立主体，紫色只承担有限信号。
2. Display、Body 和 Metadata 三种声音清楚但不互相争夺。
3. 主要阅读轴明确，信息先通过层级与空间分组。
4. 大结构保持硬朗；小圆角只落在独立下层表面或控件。
5. 面积与视觉重量来自内容意义，而不是来自容器模板。
6. 图片保留真实颜色，但系统状态仍由核心语言控制。
7. 不出现第 7 节所列的默认禁止项。

综合样张只证明这些关系可以同时成立，不得被复制为固定模板。

### 8.1 盲测方法

测试核心规范时，新执行者只能获得本文件和一个内容、结构、尺寸已经明确的 brief，不应看到既有示例或内部审核页。

建议使用同一内容测试网页首屏、单张海报和小红书单页，并判断：

- 三种结果是否明显属于同一视觉语言；
- 三种结果是否保持不同构图，而不是复制同一模板；
- 禁止项是否被稳定避免；
- 执行者是否频繁遇到本规范无法判断的问题。

若失败，应分别归因：

- 风格表现不一致：核心规范可能存在歧义；
- 平台字号、安全区、分页或交互不明确：缺少对应 Kit；
- 内容、结构或目标不明确：brief 不完整；
- 规则明确但未被执行：实现偏差，不应继续扩张核心规范。

## 9. 治理与版本

### 9.1 状态

- `observed`：从既有设计或其他来源直接观察到的证据。
- `candidate`：为了通用规范整理出的候选。
- `approved`：经过用户明确确认，可进入本规范。
- `rejected`：用户明确否决，不得在后续版本中静默恢复。

### 9.2 修改要求

每条规则修改必须记录：

- 修改内容；
- 修改原因；
- 用户决定；
- 被替代或被拒绝的旧规则；
- 生效版本。

审美候选必须先以可观察结果呈现。用户明确选择后，才能进入 `approved`。

### 9.3 版本语义

- Patch：措辞澄清，不改变视觉决定。
- Minor：新增或调整可观察规则、Token 或边界。
- Major：改变核心视觉身份或使已有作品大范围失配。

## 10. Skill 使用边界

`quiet-signal-design` Skill 只做两件事：

1. 把本规范应用到一个已经明确的设计任务。
2. 根据本规范审查一个已有设计，并指出具体符合项、违反项和不确定项。

使用者应提供尽可能明确的：

- 要设计或审查的对象；
- 确定的内容与必需结构；
- 目标环境、尺寸或技术限制；
- 需要交付到什么深度。

Skill 可以为完成明确任务做局部排版判断，但这些判断属于该作品，不自动成为 Quiet Signal 规范。

当任务缺少平台规则时，Skill 应指出缺少对应 Kit 或 brief，而不是在核心规范中发明一套平台系统。

## 11. 发布状态

本规范的视觉方向与圆角边界于 2026-08-23 获得批准。内部来源、审核图纸和决策记录不属于公开 Skill；本文件是公开包中的完整规范来源。
